# Navigation keys and Network as a tab (2026-11-20)

Owner's decisions (docs/redesign/backlog.md > Decided, 2026-11-20).

- **L2 / R2 are the rail's sections everywhere; L / R are a page's tabs.** `Shell::key` takes L2 / R2 (not while a form,
  a select mode, the picker or a playlist move has the page); `Ui::press` hands L / R to the page's area: Settings and
  Web (groups), Music and Videos (views), Playlists (back to Albums / Artists), About (groups); Manga's tabs, a
  source's, Sources', All recent's kinds and Home's filter are their own handlers. The player and the readers keep
  L / R (file, page) and L2 / R2 (chapter). Every hint bar and tab cap says it (the settings group's neighbours in the
  header too: "L Playback / Music R").
- A source's series page (no tabs): R opens the chapters sheet (was R2), L checks the source (was L2).
- **A source page's keys as the spec:** Y Filters (when the source has some), X More (`Manga::mangaSourceMore`:
  Search this source, Load this list again). Search is the third tab; its empty state says "A asks for the words".
- **Network is a tab of Files, not a rail cell.** `Browse::tabsOn()` (the places, and the connections' list) draws
  `Kit::tabs` ("Files" | "Network", caps L/R) over `lay::tabPage`; `tabsBody()` is the body under the strip, used by
  `filesLayout` and `netLayout`, so the touches test the same Rects. L / R or a tap switch (`openSection`). The forms
  and folders under them have no strip. Header crumb: "Files > Network . N connections". `Section::Network` is gone.
