# Boxes for Japanese text, and Fusion Pixel's regional builds (2026-11-21)

- The boxes were the top panel's: `cardcanvas.h` (the Preview pane, the level and note cards) drew in Pixelify Sans
  with no fallback. Its text now goes through `fontRuns` (`src/fontruns.h`), shared with `Ui::shapeRuns`.
- Fusion Pixel's builds (zh_hans, zh_hant, ja, ko, latin, zh_hk, zh_tw; release 2026.10.16) all map the same 37689
  characters: a fallback chain between them never finds a glyph another lacked. They differ only in how ~5000 are drawn.
  So only the Japanese forms are bundled, as a subset (`tools/make-ja-forms.py`, 1.1 MB, ~0.3 MB compressed), used for
  text with kana (`hasKana`, tagtext.h). Traditional isn't: nothing tells Traditional text apart reliably.
- fonts.conf rejects `*-ja-forms.ttf`, so libass never picks it for a Chinese subtitle; libass's own fallback to the
  zh_hans build was already right (subtitles keep the Simplified forms).
- Not done: the TXT viewer's fallbacks (textreader.cpp) and the web page don't use the Japanese forms.
