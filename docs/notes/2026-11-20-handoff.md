# Handoff: carrying on the redesign (2026-11-20)

For an agent picking up the redesign. Read this first, then only what a task needs.

## Where to work

- Branch **`redesign-impl`**, worktree `.claude/worktrees/rd-base` (snapshot: `redesign-2026-11-20`). Never `main`.
- Never merge to main, push to GitHub, or release: the owner decides that. Never stage `opencode.json`: commit with
  `git add -A -- . ':!opencode.json' ':!docs/redesign/__pycache__'` then `git commit -m "..."`.
- Build and test (macOS): `export SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.sdk; cmake --build build -j;
  ./build/core-test` (must end `core: all passed`).
- Look at a change: `BP_SHOTS=.scratch/shots ./build/banana-player /ABS/PATH/FILE --state-dir .scratch/st --press
  "info,shot:NAME"` (steps in docs/workflow.md; absolute media paths; generated media only, made with ffmpeg in `.scratch/`).
- To the handheld: `packaging/build-bundle.sh --quick`, then `ssh root@192.168.1.50 'killall -TERM banana-player'`, then
  `tools/push-handheld.sh root@192.168.1.50`. Never scan the network or log into another host; if the address fails,
  ask the owner.

## How to read the spec

- `docs/redesign/README.md` says what each file is. The screens live in `docs/redesign/src/screens.js` as one array,
  `SCREENS`: each entry `{id, group, name, why, notes, keys, ...}` with its drawing; find one with
  `grep -n "id:'music-album'" docs/redesign/src/screens.js` and read that entry only (its `keys` list is the key map,
  its notes the rules). The drawings use helpers from `src/kit.js` and `src/comps.js`, which mirror the C++ kit.
- `components.md` is the contract for every reusable piece (sizes, states, tokens); `backlog.md` › Decided overrides
  anything older. Where the spec and the code differ, the spec wins unless the status note says otherwise.
- To see a screen: open `docs/artifacts/handheld-redesign/index.html` (or `docs/redesign/preview.html`) and find it by
  name in the left menu.

## Components first, then screens

Every screen is built from reusable kit components, never drawn ad hoc on a page:
1. Before wiring a screen, list the pieces it needs (from its `screens.js` entry and `components.md`) and check the kit
   inventories (step 4 above) for each.
2. A missing piece is built first, in the kit: a `lay::` layout in `kitlayout.h/.cpp` + a `Ui::Kit` draw in
   `ui_kit*.cpp` + a layout test in `tests/core_test.cpp` + a gallery page (`--press gallery:variants:N`), and the
   inventory note updated. One commit.
3. Only then the screen is wired, using those pieces; a duplicate helper on a page is merged back into the kit.

## Rules that keep the owner's decisions

- Draw with `Ui::Kit` on `lay::` Rects (kitlayout.*) and test the layout in tests/core_test.cpp; touch tests the same Rects.
- Clean is the look; keys stay keys (Kit::key / iconKey / transport always Classic); High contrast is all Classic.
- Type: all Pixelify Sans. Spacing: lay::SP2..SP24, touch targets 44 or more. Colours only from theme roles.
- New drawing state goes into `signature()`. Background threads never touch Ui or Player.
- FEATURES.md for anything a user sees; one note in docs/notes/ per piece of work.
- Screenshots and media: generated or Big Buck Bunny / Sintel only. Public text never names other apps.
