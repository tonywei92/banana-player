# Handoff: carrying on the redesign (2026-11-20)

For an agent picking up the redesign. Read this first, then only what a task needs.

## Where to work

- Branch **`redesign-impl`**, worktree `.claude/worktrees/rd-base` (snapshot: `redesign-2026-11-20`). Never `main`.
- Never merge to main, push to GitHub, or release: the owner decides that. Never stage `opencode.json`.
- Build and test (macOS): `export SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.sdk; cmake --build build -j;
  ./build/core-test` (must end `core: all passed`).
- Look at a change: `BP_SHOTS=.scratch/shots ./build/banana-player /ABS/PATH/FILE --state-dir .scratch/st --press
  "info,shot:NAME"` (steps in docs/workflow.md; absolute media paths; generated media only, made with ffmpeg in `.scratch/`).
- To the handheld: `packaging/build-bundle.sh --quick`, then `ssh root@192.168.1.50 'killall -TERM banana-player'`, then
  `tools/push-handheld.sh root@192.168.1.50`. Never scan the network or log into another host; if the address fails,
  ask the owner.

## Rules that keep the owner's decisions

- Draw with `Ui::Kit` on `lay::` Rects (kitlayout.*) and test the layout in tests/core_test.cpp; touch tests the same Rects.
- Clean is the look; keys stay keys (Kit::key / iconKey / transport always Classic); High contrast is all Classic.
- Type: all Pixelify Sans. Spacing: lay::SP2..SP24, touch targets 44 or more. Colours only from theme roles.
- New drawing state goes into `signature()`. Background threads never touch Ui or Player.
- FEATURES.md for anything a user sees; one note in docs/notes/ per piece of work.
- Screenshots and media: generated or Big Buck Bunny / Sintel only. Public text never names other apps.
